# Graduated practice

Work independently in stages. Level one: predict the result for a request with slug `Team Alpha` when `team-alpha` already exists. State whether save runs, which exception is public, and whether a channel is added. Level two: two requests both observe absence, request B commits first, and request A receives `DbUpdateException`. Predict the post-failure query and public result. Level three: the database reports a unique violation for a channel row while no workspace with the normalized slug exists. Decide whether the service should translate it. Level four: explain why a fake that keeps pending Added entities in the query result cannot prove the race behavior.

For implementation practice, sketch a small decision function with inputs `precheckExists`, `saveError`, and `persistedSlugAfterError`. Keep authorization outside that function. Then compare your sketch with the actual flow in [WorkspaceService.cs](../src/NetSlack.Application/Workspaces/WorkspaceService.cs). Add one assertion that success creates both workspace and general channel, and one assertion that the original unrelated exception object is preserved. Avoid inspecting provider-specific text.

For code review practice, mark each statement true or false: “the precheck prevents races”; “all unique exceptions are slug conflicts”; “a persisted re-query can identify a winner”; “the harness proves a real database index”; “unauthenticated callers should learn slug existence.” Justify every answer with a boundary: timing, constraint ownership, persistence, test scope, or authorization.

Stretch exercise: propose behavior if the post-failure query itself fails.
