# NetSlack CRUD upskill

This course follows one bounded change in the staged NetSlack workspace flow: a create request must translate a real concurrent slug winner into the application’s `ConflictException`, while preserving the original save failure when a successful recovery query finds the slug absent. Start with the map in [01-CODEBASE-MAP.md](01-CODEBASE-MAP.md), then trace the write in [03-WORKED-CHANGE.md](03-WORKED-CHANGE.md). The production entry point is [WorkspaceService.cs](../src/NetSlack.Application/Workspaces/WorkspaceService.cs); the original baseline is [its snapshot](snapshots/src/NetSlack.Application/Workspaces/WorkspaceService.cs).

The key CRUD lesson is that a preflight query is only advisory. Two requests can both observe no row and then race at the database unique boundary. A service therefore needs both a friendly precheck and a database-backed recovery path. The recovery path must use a persisted query, because an ORM’s in-memory change tracker is not evidence that another transaction committed. This course also distinguishes the user-visible authorization boundary, the normalized slug data boundary, and the database constraint boundary. It does not claim transaction isolation, retry orchestration, or provider-specific exception decoding.

Work through [05-PRACTICE.md](05-PRACTICE.md) before reading [06-SOLUTIONS-AND-REVIEW.md](06-SOLUTIONS-AND-REVIEW.md). The executable evidence is the source-linked harness at [Program.cs](../tests/NetSlack.ScopeHarness/Program.cs), which runs focused cases against the actual service and domain types. The harness contracts are explicit test doubles; they model a persisted concurrent winner and an unrelated failure, but they do not prove a live EF provider’s SQL translation. [VERIFICATION.md](VERIFICATION.md) records that limit and the unavailable native .NET8 runner honestly.

Reading order: 01 map, 02 concepts, 03 worked change, 04 testing, 05 practice (each exercise has a **Check**), then 06 answers and verified review findings, 07 trace lab, and VERIFICATION. One caution before 02: the recovery query's `AsNoTracking` is not what makes it reach the database; any EF Core LINQ query over a `DbSet` does (06, finding B).

Keep the original test learning nearby: [WorkflowTests.cs](../tests/NetSlack.Application.Tests/WorkflowTests.cs) and [its snapshot](snapshots/tests/NetSlack.Application.Tests/WorkflowTests.cs) show the project’s existing integration style. The course is delivered with the reviewed source change and its test evidence. It does not run migrations or upgrade the original application target.
