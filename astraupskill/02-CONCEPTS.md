# Concepts: CRUD, races, and boundaries

CRUD correctness has two layers here. The read-before-create check gives a fast, readable response for an already-existing slug. The unique database constraint is the final authority when two creates interleave. Treating the precheck as sufficient creates a time-of-check/time-of-use bug: request A and request B can both read absence. Only one can commit. The loser needs a stable application result instead of leaking provider text.

The change uses a persisted re-query after `DbUpdateException`. If the normalized slug is now present, the service raises `ConflictException`; otherwise it preserves the original exception. This is provider-neutral control flow. It avoids relying on constraint names or message casing, which vary across PostgreSQL, SQLite, and SQL Server. It also avoids treating every unique violation as a workspace conflict: another table may have failed. A real EF query observes database state rather than merely the local Added collection; the harness models that distinction by replacing pending rows with a concurrent persisted winner on failed save.

Normalization is part of the key: `Same Slug`, `same-slug`, and surrounding whitespace resolve to one comparison value. Authorization comes first, so unauthenticated callers cannot create records or learn whether a slug exists. The owner membership and general channel are part of the create transaction’s intended result; a success test checks both. The service does not promise automatic retry, distributed locking, or recovery from a database outage.

The existing project uses a database-enforced uniqueness model; see [WorkspaceService.cs](../src/NetSlack.Application/Workspaces/WorkspaceService.cs), [Workspace.cs](../src/NetSlack.Domain/Workspaces/Workspace.cs), and [WorkflowTests.cs](../tests/NetSlack.Application.Tests/WorkflowTests.cs). The staged tests are honest contract tests, not a live provider test. A reviewer should therefore approve the exception classification logic while requesting an environment with the project’s native SDK and database before claiming end-to-end coverage.
