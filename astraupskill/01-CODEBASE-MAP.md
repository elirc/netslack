# Codebase map: one workspace create

Begin at [WorkspaceService.cs](../src/NetSlack.Application/Workspaces/WorkspaceService.cs). `CreateAsync` authenticates the caller, trims and lowercases the command slug, checks whether that normalized value already exists, creates a `Workspace`, creates its `general` channel, adds both aggregates to the unit-of-work abstraction, and saves. Its return value is a DTO built from the new workspace. That order matters: authentication is an authorization boundary; normalization is a data boundary; the query is a race-prone read; `SaveChangesAsync` is the durable boundary.

The domain objects live under [src/NetSlack.Domain](../src/NetSlack.Domain). `Workspace.Create` creates the owner membership and enforces domain invariants; `Channel.Create` supplies the initial channel. The application layer deliberately depends on `IAppDbContext` and `ICurrentUser`, which makes a narrow harness possible without copying service logic. The existing test fixture is [WorkflowTests.cs](../tests/NetSlack.Application.Tests/WorkflowTests.cs). The exact pre-change files are preserved under [snapshots](snapshots/).

Trace the four paths. An existing slug returns before writes. A missing slug normally creates both records. A concurrent writer can commit after the check and make save fail; the changed service asks the database whether that slug now exists and maps only that observation to conflict. A different save error has no matching persisted workspace and is rethrown. The source-linked harness in [tests/NetSlack.ScopeHarness](../tests/NetSlack.ScopeHarness) exercises each path.

Map dependencies before changing code: `WorkspaceService` needs queryable sets, async query operators, domain factories, and application exceptions. The harness supplies contracts for those edges while compiling the real service and domain source. This is useful for control-flow evidence, but it cannot validate EF provider translation, a real unique index, or production transaction isolation. Those are explicit follow-up boundaries rather than assumptions.
